RSA and Primality Testing

Section 31.7 builds the RSA public-key cryptosystem from the last lesson's arithmetic and proves that decryption inverts encryption. Section 31.8 finds the primes it needs: random numbers near n are prime about once in ln n tries, Fermat's test is fooled by pseudoprimes and Carmichael numbers, and the Miller-Rabin test, which also looks for nontrivial square roots of 1, errs with probability at most 2^(−s) after s random bases. Core ideas

What this lesson establishes

Three ideas: a key anyone may know, the evidence that proves a number composite, and the error a randomized test leaves.

1

Public and secret keys

Each participant publishes one key and keeps the other. Applying the public key and then the secret one, or the other way round, returns the message; the system is secure only if the secret transformation cannot be computed from the public one in any practical time.

2

Witness

A base a that proves an odd number n composite. In the Miller-Rabin test, a is a witness if aⁿ⁻¹ is not 1 modulo n, which Fermat's theorem forbids for a prime, or if squaring along the way reveals a square root of 1 other than ±1, which no prime modulus has. A base that is not a witness proves nothing.

3

One-sided error

The test's answer composite is always right; its answer prime can be wrong, when every base it tried happens not to be a witness. Each independent random base is a witness with probability at least 1/2 for a composite, so s bases leave an error of at most 2^(−s).

The material

The chapter's argument first, then the count

Read sections 31.7 and 31.8 in your own copy first, and the opening of 31.9 if you want to know why factoring is believed hard. The lesson sets out RSA and the Miller-Rabin test in its own words, builds one RSA key by hand, and counts witnesses in the lab.

“The RSA public-key cryptosystem relies on the dramatic difference between the ease of finding large prime numbers and the difficulty of factoring the product of two large prime numbers.” Section 31.7 builds the system and Section 31.8 supplies the easy half, a fast way to find primes. Section 31.9, on factoring, is starred and named here only; it is the hard half, and no fast method is known.

A public-key cryptosystem gives each participant a public key P and a secret key S that describe inverse permutations of the set of messages. To send Alice a message, Bob applies her public key; only Alice can apply the secret inverse. To sign, Alice applies her secret key, and anyone can check the signature with her public one. The section's whole difficulty is to publish a function without revealing how to invert it.

Theorem · RSA, in five steps

Choose two large primes p and q and let n = pq. Compute φ(n) = (p − 1)·(q − 1). Choose a small odd e coprime to φ(n). Let d be the inverse of e modulo φ(n), by extended Euclid. Publish (e, n), keep (d, n); encrypt by C = Mᵉ mod n and decrypt by M = Cᵈ mod n.

Why does decryption work? Theorem 31.36 checks it modulo p and modulo q separately. Since ed = 1 + k·(p − 1)·(q − 1), modulo p the power M^(ed) is M times a power of M^(p−1), which is 1 by Fermat's theorem when p does not divide M, and both sides are 0 when it does. The same holds modulo q, and the Chinese remainder theorem joins the two into M^(ed) ≡ M (mod n). Encryption and decryption are each one modular exponentiation, and in practice RSA encrypts only a short key for a faster symmetric cipher, which the authors describe as a hybrid system.

Example · A key small enough to check

Take p = 43 and q = 67: n = 2881 and φ(n) = 42·66 = 2772. Choose e = 5, which is coprime to 2772. Extended Euclid gives 5·1109 − 2·2772 = 1, so d = 1109. The message M = 1000 encrypts to 1000⁵ mod 2881 = 962, and 962¹¹⁰⁹ mod 2881 = 1000. Anyone who could factor 2881 could repeat this arithmetic, which is why real keys use primes hundreds of digits long.

Section 31.8 asks how such primes are found. By the prime number theorem the number of primes up to n is about n/ln n, so a random number near n is prime with probability about 1/ln n, and about ln n random tries find one, about 710 for 1024-bit numbers, half that if only odd numbers are tried. What is needed is a fast test. Trial division takes about √n steps, exponential in the number of bits.

Fermat's theorem gives a fast test that almost works: if n is prime then aⁿ⁻¹ ≡ 1 (mod n) for every a from 1 to n − 1. PSEUDOPRIME checks this for a = 2 and is wrong only on base-2 pseudoprimes, composites that pass, of which there are 22 below 10,000. Trying more bases does not repair it, because Carmichael numbers pass for every base coprime to them. The Miller-Rabin test adds a second check. Write n − 1 = 2ᵗ·u with u odd, compute a^u mod n, and square it t times to reach aⁿ⁻¹. If some square is 1 while the value before it was neither 1 nor n − 1, that value is a nontrivial square root of 1 and n is composite (Corollary 31.35); if the last value is not 1, Fermat's test fails. Either way WITNESS returns true.

Theorem · Theorems 31.38 and 31.39, in short

If n is an odd composite, at least (n − 1)/2 of the bases 1 to n − 1 are witnesses. MILLER-RABIN tries s bases chosen independently at random, so if n is composite it answers prime with probability at most 2^(−s), and if n is prime it always answers prime.

The authors add two remarks. The bound is about the test's coin flips, not about how likely a given n is to be prime, and Bayes's theorem shows that for a random 1024-bit number about nine trials are needed just to outweigh the prior odds against primality; they suggest s = 50 for almost any use. And the true count is better than the theorem: an improved argument shows that at most (n − 1)/4 bases are non-witnesses, some n have exactly that many, and for a random odd composite far fewer are expected.

Now the lab, the one the Algorithms Subject's lesson Witnesses, Liars, and One-Sided Error uses. Its slider n runs over odd numbers up to 2,047, and for each it tests every base from 2 to n − 2, so the counts are exact. It traces the chain for one chosen base, counts witnesses and non-witnesses, counts Fermat's witnesses beside them, and gives the exact chance that a chosen number of random bases all fail to testify. It differs from the book in three ways. Its letters are swapped: it writes n − 1 = d·2ˢ with d odd, where the book writes 2ᵗ·u, and it calls the number of bases t, where the book calls it s. Its bound is (1/4) to the number of bases, from the improved argument, not Theorem 31.39's 2^(−s), and a tile checks that at least three quarters of the bases are witnesses, not Theorem 31.38's half. And it leaves out the bases 1 and n − 1, which never testify, where the book draws from 1 to n − 1.

The lesson's number is preset psp2047, 2047 = 23 · 89. Here n − 1 = 2·1023, so t = 1, and 2¹¹ = 2048 ≡ 1, so 2¹⁰²³ = (2¹¹)⁹³ ≡ 1: base 2 yields no testimony, and a test that tried only base 2 would call 2047 prime. The lab counts 1,804 witnesses among the 2,044 bases, 451/511, 0.8826, and 240 non-witnesses, the smallest of them 2. Base 3 is a witness: 3¹⁰²³ ≡ 1565 and 1565² ≡ 1013, not 1. In the book's count over 1 to 2,046 there are 242 non-witnesses, far under the (n − 1)/2 = 1023 that Theorem 31.38 allows.

Write n − 1 = d · 2^s with d odd. The chain is a^d then repeated squaring. If it never reaches 1 or n−1 then a is a witness and n is composite — proved, not suspected. A square of something other than 1 or n−1 landing on 1 is a nontrivial square root, and its gcd with n is a factor.

Method

One base of the Miller-Rabin test

Factor out the twos from n − 1 before anything else.

1

Write n − 1 as 2ᵗ·u

Divide n − 1 by 2 until it is odd. The odd part is u and the number of halvings is t.

2

Raise a to the power u

Use repeated squaring. If the result is 1 or n − 1, the base gives no testimony; stop.

3

Square up to t − 1 times

Square modulo n. Reaching n − 1 ends the chain with no testimony. Reaching 1 from a value other than ±1 is a nontrivial square root of 1: a is a witness.

4

Read the verdict

If the chain never reached n − 1, a is a witness and n is composite. Otherwise this base proves nothing, and the test tries another.

5

Do it on a number of your own

Pick an odd composite of your own below 2,047 with two prime factors, predict whether base 2 is a witness by hand, then set the lab's n to it and compare its witness count with (n − 1)/2.

Decrypting with the Chinese remainder theorem

Check the example's decryption of C = 962 without computing 962¹¹⁰⁹ modulo 2881 directly, by working modulo 43 and 67 as Theorem 31.36's proof does.

M = 1000 ≡ 11 (mod 43) and ≡ 62 (mod 67) d = 1109 ≡ 17 (mod 42) and ≡ 53 (mod 66) 962 ≡ 16 (mod 43); 16¹⁷ ≡ 11 (mod 43) 962 ≡ 24 (mod 67); 24⁵³ ≡ 62 (mod 67) the CRT joins 11 (mod 43) and 62 (mod 67) into 1000 (mod 2881)

Fermat's theorem lets each exponent drop modulo p − 1 or q − 1, and the two small powers recover M's remainders. Real implementations decrypt this way because the two half-size powers are cheaper than one full-size power; the secret primes are needed to do it.

Common mistakes

1
Reading a passed test as proof of primalityThe answer composite is a proof; the answer prime is only the absence of one. On 2047, base 2 gives no testimony, and a test that stopped there would accept a composite. The lab shows 240 such bases out of 2,044; the guarantee is about the chance of drawing only those, which s random bases drive below 2^(−s).
2
Trusting Fermat's test with more basesAdding bases helps against most pseudoprimes but not against Carmichael numbers, which satisfy aⁿ⁻¹ ≡ 1 for every base coprime to them, so only bases sharing a factor with n expose them. The square-root check is what makes the Miller-Rabin test immune: for every odd composite at least half the bases are witnesses.
3
Computing d modulo n instead of modulo φ(n)The decryption exponent is the inverse of e modulo φ(n) = (p − 1)·(q − 1), because exponents work modulo p − 1 and q − 1 by Fermat's theorem. An inverse taken modulo n, or n − 1, has no such property and does not decrypt in general; computing φ(n) needs p and q, which is where the secrecy lies.
