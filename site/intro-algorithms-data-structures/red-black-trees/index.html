Red-Black Trees and Rotations

Sections 13.1 and 13.2 add a colour to each node of a search tree, state the five red-black properties, define black-height, and prove that a tree obeying them has height at most 2 lg(n + 1). They then give the rotation, the local restructuring that later sections use to restore the properties without breaking search-tree order. Check a tree's properties by hand, then let the lab check five trees and point to the first node where each property fails.

Core ideas

What this lesson establishes

Three ideas carry the first two sections. The next lesson's insertion and deletion are written in terms of all three.

1

The red-black properties

Five rules on a search tree whose nodes are coloured: every node is red or black; the root is black; every leaf, the NIL below a node with a missing child, is black; a red node's children are both black; and from each node, every path down to a leaf passes the same number of black nodes.

2

Black-height

For a node x, the number of black nodes on any path from x down to a leaf, not counting x and counting the NIL leaf. Property 5 is exactly the statement that this number is the same on every path, so bh(x) is well defined. The tree's black-height is its root's.

3

Rotation

A local change at a node x and one child y that makes y the parent and x its child, handing y's inner subtree across to x. A left rotation lifts x's right child, a right rotation its left. It changes a constant number of pointers and keeps the inorder sequence, so the search-tree property survives.

The material

The chapter's argument first, then the check

Read the chapter opening and sections 13.1 and 13.2 in your own copy first. The lesson sets out the properties, the lemma and the rotation in its own words, checks one tree by hand, and then lets the lab check five.

A red-black tree, the authors write in Section 13.1, constrains colours so that “no such path is more than twice as long as any other, so that the tree is approximately balanced.” The paths are the ones from the root down to a leaf, and the claim is the chapter's whole purpose: Chapter 12 made every operation cost the height, and this chapter keeps the height logarithmic whatever order the keys arrive in. This lesson reads the opening and sections 13.1 and 13.2.

Section 13.1 starts with a convention. Wherever a node lacks a child, the missing child is treated as a leaf, an external node, and the key-bearing nodes are internal. Every internal node then has exactly two children, and the properties can speak of leaves without exceptions. The book uses one sentinel, T.nil, a black node standing for every leaf and for the root's parent, which is the economy Section 10.2 recommended: one extra object per tree rather than one per missing child. Drawings usually leave the leaves out.

Definition · The five red-black properties, in the book's order

1. Each node carries one of two colours, red or black. 2. The root must be black. 3. Each leaf, T.nil, is black. 4. A red node has two black children. 5. From any node, every downward path to a leaf meets equally many black nodes.

Properties 4 and 5 together do the work. By property 5 every path from the root to a leaf has the same number of black nodes, the black-height; by property 4 no two reds are adjacent, so reds can at most alternate with blacks. The shortest possible path is all black and the longest alternates, which is the factor of two in the quotation. The other three properties make the count well defined: every node has a colour, the leaves are black, and the root is black, which a fix-up can always restore by recolouring it.

Theorem · Lemma 13.1

If a red-black tree has n internal nodes, its height is at most 2·lg(n + 1).

The proof has two steps. First, by induction on height, the subtree rooted at any node x holds at least 2^bh(x) − 1 internal nodes: a leaf holds 0, and each child of an internal node has black-height at least bh(x) − 1, so x's subtree holds at least 2·(2^(bh(x) − 1) − 1) + 1 nodes, which is the claim. Second, property 4 means black nodes make up at least half of every root-to-leaf path, the root left out, so a tree of height h has black-height at least h/2. Then n ≥ 2^(h/2) − 1, and taking logarithms gives the bound. Search, minimum, maximum, successor and predecessor therefore run in O(lg n) with no change to Chapter 12's code.

Insertion and deletion are a different matter, since Chapter 12's versions can break the properties. Section 13.2 supplies the tool for repairing them. LEFT-ROTATE at a node x whose right child y is not T.nil makes y the root of the subtree, makes x y's left child, and gives y's former left subtree to x as its right subtree. RIGHT-ROTATE is the mirror image. Each runs in O(1) and changes only pointers; the inorder sequence, and with it the search-tree property, is untouched. Now the lab, which checks a tree against all five properties and against search-tree order. You write the tree as records, one per node: its key, its colour, and its parent's key, or a dash for the root; a child smaller than its parent is its left child. The tiles say whether the tree is red-black, then each property in turn, holding or failing at the first node found, then search-tree order, the number of nodes, the root's black-height, the height, and the bound of Lemma 13.1. The lab's height counts the edges down to the deepest leaf, NIL included, as the lemma's proof does, so it is one more than Chapter 12's height of the same tree.

The worked example valid-eight is the tree of the worked example below: every property holds, 8 nodes, black-height 2, height 4, against the bound 2 lg 9 ≈ 6.34. red-child adds a red 30 below the red 33, and property 4 fails at 33 while property 5 still holds, since a red node adds no black. unequal-black blackens 52, and property 5 fails at 41: one black node down its left side, two down its right. red-root is a tree whose only fault is its red root, the fault RB-INSERT-FIXUP's last line repairs by recolouring. And out-of-order is coloured correctly and is not a search tree: 30 sits in 26's left subtree, which the colours cannot detect.

Each verdict is about the tree on screen, and the lemma is about every tree. No tree of 8 nodes has height below 4 in the lab's count, and the lemma says no valid red-black tree of 8 nodes can reach 7; only its proof shows that.

Exercise

Check by hand the tree with root 20 black; 10 black and 30 red below it; 5 red below 10; 25 and 40 black below 30; 35 and 45 red below 40. Give every node's black-height. Then colour 40 red and 35 and 45 black, and say which property fails, at which node, and whether the black-height changes. Type both trees into the lab to check.

Method

Checking a red-black tree by hand

Four steps on a drawn tree, then one in the lab.

1

Draw the leaves

Hang a black NIL leaf wherever a node lacks a child. Every internal node now has two children, and properties 3 and 5 can be read off the drawing.

2

Check the colours locally

The root must be black, and no red node may have a red child. These are properties 2 and 4, and each needs only a node and its children.

3

Compute black-heights from the bottom

A NIL has black-height 0. For each node, add 1 to a child's black-height if the child is black; the two children must give the same number, or property 5 fails at that node.

4

Apply the lemma

With n internal nodes, check 2^bh − 1 ≤ n at the root and the height against 2·lg(n + 1).

5

Check a tree of your own

Draw a red-black tree of nine to twelve nodes, type it into the lab, and confirm your black-height. Then recolour one node so that exactly one property fails, and predict which node the lab will name.

Property 5 holds at every node because each node's two children give the same count; at 26 the red 14 adds nothing and the black 41 adds one, and both sides come to 2. Property 4 holds because the reds, 14, 5, 33 and 52, all have black children or NIL leaves. The longest path alternates red and black for part of its length, which is as long as the rules allow a path to be.

Common mistakes

1
Reading the red-black rules as making the tree perfectly balancedThe rules bound the longest root-to-leaf path at twice the shortest, not at one more. The worked example's tree has paths of 3 and 4 edges to its leaves, and Lemma 13.1 allows a valid tree of 8 nodes a height of up to 6. What the rules buy is a guarantee of O(lg n) height for every insertion order, with a constant of 2, at the price of one bit per node.
2
Counting black-height wronglyThe book's bh(x) leaves x out and counts the NIL leaf. Counting x, or leaving out the leaf, gives a number one off, and Lemma 13.1's 2^bh(x) − 1 then stops matching small cases. In the worked example the root 26 has black-height 2: the path 26, 14, 9 and its leaf passes 9 and the leaf, and not 26.
3
Thinking the colours can stand in for the search-tree propertyThe colours constrain shape and say nothing about key order. The lab's out-of-order tree satisfies all five properties and is not a search tree, because 30 sits in 26's left subtree. A red-black tree is first a binary search tree, and the five properties are added to it.
