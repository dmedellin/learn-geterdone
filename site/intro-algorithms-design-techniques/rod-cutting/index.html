Core ideas

What this lesson establishes

Three ideas carry the section, and the rest of the chapter reuses all three.

1

Overlapping subproblems

A recursion has overlapping subproblems when it asks the same smaller question many times over. Rod cutting asks for the best revenue from a rod of length j for every j below n, again and again in different branches. Divide-and-conquer, by contrast, usually splits into pieces that never recur.

2

Memoized and bottom-up

Two ways to solve each subproblem once. Top-down with memoization keeps the recursion and stores each answer the first time it is computed. Bottom-up orders the subproblems by size and solves the smallest first, so that every answer a step needs is already in the table. The two have the same asymptotic running time.

3

The subproblem graph

One vertex per distinct subproblem and an arc from each subproblem to every subproblem it consults directly. It is the recursion tree with repeated nodes merged. Its size estimates the running time, and bottom-up order is a reverse topological order of it.

The material

The chapter's argument first, then the count

Read the opening of Chapter 15 and Section 15.1 in your own copy first. The lesson sets out the argument in its own words, fills one revenue table by hand, and then sets the three routes' call counts side by side.

“A dynamic-programming algorithm solves each subsubproblem just once and then saves its answer in a table, thereby avoiding the work of recomputing the answer every time it solves each subsubproblem.” That sentence, from the first paragraph of Chapter 15, is the whole method; the authors add at once that the word programming here means a tabular method, not writing code. This lesson reads the chapter's opening and Section 15.1, the first of its five examples.

The opening sets the method beside divide-and-conquer. Both solve a problem by combining solutions to subproblems. Divide-and-conquer splits into disjoint pieces; dynamic programming applies when the subproblems overlap, so that subproblems share subsubproblems, and it saves each answer in a table so that no subsubproblem is solved twice. The usual targets are optimization problems, where many solutions exist and one with the best value is wanted, and the authors note the article: an optimal solution, since several may tie. They give four steps: characterize the structure of an optimal solution, define its value recursively, compute that value, usually bottom-up, and construct a solution from what was computed. The fourth is optional when only the value is wanted.

Definition · The rod-cutting problem

Given a rod of n inches and a price pᵢ for a piece of length i, for i from 1 to n, find the largest revenue rₙ obtainable by cutting the rod into pieces of whole-inch lengths and selling them. Cuts cost nothing, and selling the rod whole is allowed.

There are 2ⁿ⁻¹ ways to cut the rod, because at each of the n − 1 inch marks you independently cut or do not. The authors first write the best revenue as the larger of selling whole and every split into two pieces, each then cut optimally; that the best solution is built from best solutions to the two pieces is what they call optimal substructure. They then simplify: view every cutting as a first piece of length i taken from the left, which is sold as it is, and a remainder of length n − i, which may be cut further. Then rₙ is the largest of pᵢ + rₙ₋ᵢ over i from 1 to n, with r₀ = 0, and only one subproblem, the remainder, is consulted per choice.

Theorem · The plain recursion makes 2ⁿ calls

CUT-ROD computes the recurrence directly: for each first piece i it calls itself on n − i. If T(n) counts the calls made on a rod of length n, including the first, then T(0) = 1 and T(n) = 1 + T(0) + T(1) + ⋯ + T(n − 1), which solves to T(n) = 2ⁿ (Exercise 15.1-1). The recursion tree has one leaf for each of the 2ⁿ⁻¹ cuttings.

The authors describe what that means in practice: at n = 40 the program runs for minutes, likely more than an hour, and each extra inch roughly doubles the time. The waste is plain in the recursion tree: a call on length j calls every shorter length, so the length-1 subproblem alone is solved 2ⁿ⁻² times. Yet there are only n + 1 distinct subproblems, the lengths 0 to n. Dynamic programming trades memory for time: solve each length once, store it, and look it up afterwards.

Section 15.1 gives both ways of doing that. MEMOIZED-CUT-ROD keeps CUT-ROD's shape but first checks an array of answers, initialised to a value meaning unknown, and records each answer before returning it. BOTTOM-UP-CUT-ROD drops the recursion: it fills r[0..n] in increasing order of length, so that r[j − i] is always ready when r[j] needs it. Solving length j tries j first pieces, so both versions do 1 + 2 + ⋯ + n = n·(n + 1)/2 iterations of the inner step, an arithmetic series, and both run in Θ(n²). The bottom-up version usually has the better constant, with no calls to pay for; the memoized one wins only when some subproblems need never be solved.

The subproblem graph makes the count general. For rod cutting it has a vertex for each length 0 to n and an arc from j to every shorter length, n·(n + 1)/2 arcs in all. The bottom-up method visits the vertices in reverse topological order, so that every vertex comes after all the vertices it points to, and the memoized method is a depth-first search of the graph (Chapter 22's terms). When the work at a subproblem is proportional to its out-degree, as here, the running time is linear in the graph's vertices and arcs.

The last step recovers the cutting itself. EXTENDED-BOTTOM-UP-CUT-ROD stores, beside each r[j], the size s[j] of the first piece that achieved it, keeping the first i that wins because its comparison is strict. PRINT-CUT-ROD-SOLUTION then prints s[n], moves to n − s[n], and repeats until nothing is left. Here is the whole table for this lesson's price list, eight lengths with prices 1 4 8 9 14 15 19 21.

j 1 2 3 4 5 6 7 8 p(j) 1 4 8 9 14 15 19 21 r(j) 1 4 8 9 14 16 19 22 s(j) 1 2 3 1 5 3 7 3 cut 8: s(8) = 3, then s(5) = 5 revenue 8 + 14 = 22

Two rows reward a second look. At j = 6 two 3-inch pieces earn 16 against 15 for the whole rod, so s(6) = 3. At j = 7 the whole rod at 19 beats every split, so s(7) = 7. And the best cutting of the 8-inch rod contains the best cutting of its 5-inch remainder, which is optimal substructure in one line of the table.

The preset eight-inch is the table above: revenue 22, pieces 3 + 5, 256 calls for the plain recursion against 37 for the memoized one, 128 cuttings and 36 inner-loop runs. The memoized count is the 36 recursive calls of the inner loop plus the first. ten-inch adds prices 24 and 27: revenue 28 from 5 + 5, and 1,024 calls against 56. whole-is-best prices six lengths at 1 3 6 10 15 21, where every cut loses money, and the lab prints 6 (no cut). twenty-inch prices twenty lengths at the odd numbers 1 to 39, so each cut costs a dollar: 1,048,576 calls for the plain recursion, 211 memoized, 210 bottom-up.

Those last figures are the whole chapter in two numbers, and the honest reading of them is narrow. The 211 is a count on one price list. The Θ(n²) bound holds for every price list, because the arithmetic series does not depend on the prices at all; the proof says so, and the count only agrees.

Method

Filling a revenue table by hand

Four steps fill the table; the fifth uses prices of your own.

1

Write the prices in a row

Lengths 1 to n across the top, pⱼ beneath, and an empty row each for r(j) and s(j). Set r(0) = 0 to the left.

2

Fill r(j) from left to right

For each j, add pᵢ + r(j − i) for every first piece i from 1 to j, and write the largest. Every r(j − i) you need is already to the left: that is the bottom-up order.

3

Record the first piece that won

Write the smallest i that achieves the maximum as s(j). Ties go to the smaller piece, as the book's strict comparison does.

4

Read off the cutting

From n, write s(n), move to n − s(n), and repeat until you reach 0. Add the prices of the pieces and check that they make r(n).

5

Do it on a price list of your own

Write prices for lengths 1 to 7, fill the table by hand, then type them into the lab: its revenue and pieces must match yours, its memoized count must be 29 and its bottom-up count 28.

Common mistakes

1
Thinking the table changes the recurrenceMemoization and bottom-up order change how often each subproblem is solved, never what is computed: all three routes evaluate the same recurrence and return the same revenue. On the lesson's twenty-inch preset the plain recursion would make 1,048,576 calls and the memoized one 211, and the lab's revenue is the same 39 by every route. The exponential cost was repetition, not a harder computation.
2
Counting calls when you mean subproblems2ⁿ is the number of calls the plain recursion makes; the number of distinct subproblems is n + 1. The running time of a dynamic program is set by the second number and the work per subproblem, here Θ(n²) in all. Mixing the two hides exactly the overlap the method exploits.
3
Reading s(n) as the whole answers(n) is only the first piece of an optimal cutting. The rest comes from the remainder's entry, s(n − s(n)), and so on to zero. In the lesson's table s(8) = 3, and the cutting is 3 + 5 only because s(5) = 5.
