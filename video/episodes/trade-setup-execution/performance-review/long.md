@chapter The question
@title text="Performance Review" sub="Trade Setup & Execution" art=thumb
You've kept a journal for a while. The total is slightly positive. So everything's fine? Maybe. Or maybe one setup is carrying the whole thing, and another is quietly losing money underneath it.

@words text="Segment before concluding"
This lesson analyzes journal data by setup, direction, plan adherence, execution quality, and mistakes. And then it defines one measurable improvement for the next sample. Just one.

@words text="Process and measurement" sub="no live data, no recommendations, no signals"
As with the rest of this course, it teaches process and measurement. It doesn't give live market data, personal recommendations, or trade signals.

@chapter Three ideas
@art aggregate-hides
First, segment before concluding. Aggregate performance can hide weak setups, weak directions, weak regimes, or costly execution behavior. Strong setups can mask weak ones. Picture two setups in one journal. Together they look fine. Split apart, one is doing all the work, and the other is giving some of it back.

@art followed-vs-deviated
Second, process and outcome. Compare plan adherence and execution quality with the financial results, instead of reviewing profit alone. Disciplined trades can mask costly deviations, unless you split them apart. Put the followed plan trades in one column and the deviations in another, and the cost of not following the plan becomes visible.

@art one-change
And third, one improvement at a time. Select one high impact change, define a sample, and measure whether it improves the next review period. If you change several things at once, the next result can't tell you which change helped or hurt.

@chapter The process
@list heading="Review process" items="Validate the journal@Validate the journal|Calculate core metrics@Calculate core metrics|Segment the data@Segment the data|Define one next action@Define one next action"
There are four steps, at a stable review cadence. Validate the journal. Calculate core metrics. Segment the data. And define one next action.

@words text="Validate" sub="completeness · sample size · rule consistency · missing fields"
Validating comes first, because a review is only as good as its data. This is where the journal habits pay off. Missing entries or inconsistent tags would distort every number that follows. Check completeness, sample size, rule consistency, and whether important fields are missing.

@list heading="Core metrics" items="Expectancy@expectancy|Win rate and payoff@win rate|Drawdown@drawdown|Adherence and execution score@adherence"
Then calculate the core metrics. Review expectancy, win rate and payoff, drawdown, and then plan adherence and execution score, next to each other.

@art segment-split
Then segment. Compare setup, direction, timeframe, regime, mistakes, and followed plan trades against deviated ones. In the lab you filter by setup, direction, plan adherence, and a minimum execution score, and watch the diagnostic summary change.

@chapter One rule
@words text="Focus · next review sample · target adherence %"
Finally, define one next action. The lab's improvement rule has a focus, a next review sample, and a target plan adherence percentage. A measurable rule, and a fixed sample, before you review again. Both are decided now, before the next trades come in, not afterwards.

@art review-cycle
Then the cycle repeats. Trade the next sample under the one new rule, journal it, and review it the same way. Change is made only when the evidence is enough for the decision.

@chapter Where people slip
@list heading="Common mistakes" items="Changing many variables after one review@The first|Using aggregate metrics only@The second|Treating a small sample as certainty@The third|Optimizing only for net profit@And the fourth"
The first mistake is changing many variables after one review. The second is using aggregate metrics only. The third is treating a small sample as certainty. And the fourth is optimizing only for net profit, when a practical system also has to fit drawdown, streaks, execution reliability, and risk limits.

@art small-sample
That third one is easy to fall into. A pattern from a handful of trades should become a hypothesis, not a permanent rule. You test it in the next sample, and only then do you decide whether it holds up.

@chapter Try it
@words text="Load · segment · one weakness · one rule"
Here's the lesson's standard. Load a journal, segment it, name the one weakness the data supports, and write the rule for it. The rule has a sample size and a measurable target, and it changes one thing. That way, when the next review comes, you'll know exactly what you changed, and whether it helped.
